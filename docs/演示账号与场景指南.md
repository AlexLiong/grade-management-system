# 演示账号与场景指南

本文说明**演示系统各项功能时该用哪个账号**。所有账号的初始密码都是 `passwd`。

数据由 `data-service` 的 `DemoInitializer` 在启动时写入，规模为：
**4 个学院 / 8 个专业 / 21 个班级 / 205 个账号（187 名学生）/ 155 个教学班 / 1354 条选课 / 1354 条成绩 / 1 个进行中的选课批次**。

## 0. 开始演示之前

### 启动

```powershell
.\scripts\start.ps1              # 启动全部服务
.\scripts\start.ps1 -ResetDb     # 需要「全新数据」时加这个开关
```

启动后访问 **https://127.0.0.1:5173** （Vite 开发服务器；自签证书，浏览器提示时选择继续访问）。

### 两个必须知道的行为

1. **数据只在需要时重建。** 库里有账号且结构版本一致时，启动日志是
   `数据库已有 205 个账号且结构版本一致，跳过初始化。`——这是秒级的快路径。
   只有「结构版本变化」「显式 `-ResetDb`」「业务表为空」三种情况才整库重建。
   **整库重建约需 1–2 分钟**（205 个账号逐个算 BCrypt 密码哈希，这是有意设计的慢）。

2. **端到端测试脚本会在库里留下测试课程与测试选课批次。**
   系统没有「删除课程 / 删除选课批次」的接口，所以这些残留由 `DemoInitializer.purgeTestArtifacts()`
   **在每次启动时自动清理**，启动日志会打印：
   `已清除 N 门测试课程、N 条选课、N 条成绩、N 个测试选课批次（另有 N 条选课流水）`。
   清理发生在数据写入之前，不会误删演示数据。

   > **要正式演示之前，先重启一次服务**（不必加 `-ResetDb`），让残留被清掉即可。
   > 本项目的实测记录：`-ResetDb` 重建时这条日志是
   > `[DemoInitializer] 已清除 20 门测试课程、48 条选课、0 条成绩、0 个测试选课批次（另有 96 条选课流水）。`
   > （完整五条启动日志与重建后复核见 [testing.md](testing.md) 的「第七轮（R7）说明 → 演示数据恢复」）。
   > 当前库里已经是干净数据：155 个教学班全是「有人选课、有成绩」的课，没有测试课程、没有空壳课程。

### 演示前自检

登录 `admin` → 左侧导航最后一项 **安全审计** → 页面顶部显示
「成绩与独立账本一致 / 核查 1354 条 / 异常 0 条 / 待同步 0 条」即为数据完好。

## 2. 功能演示场景

### 场景一：学业预警（老师视角）

> **用什么账号**：`t1102` 李老师

1. 用 `t1102` 登录，进入 **课程成绩**
2. 上方课程下拉选择 **2026-1 · 人工智能导论（CS403）**（这门有 9 名学生）
3. 页面下方 **学业预警** 区块点「生成预警」
4. 预期看到：
   - 模型信息：`历史年份 2020 / 2021 / 2022 / 2023 / 2024 / 2025`、`51 条训练样本`、验证 RMSE
   - **9 行预测结果**：每名学生给出「线性回归总评 / 决策树总评 / 估计区间 / 学业状态（正常 / 临界风险 / 挂科预警）」
5. 再切换到 **2026-1 · 程序设计基础（CS102）** 重复一次 → 应该有 **2 行**（就是这个重修班的 2 名学生）

> **为什么是这两门课**：学业预警只能预测「已录入平时与实验、**期末还没考**」的学生。
> 2026-1 的课都是这种状态，所以有结果；已经出分的历史课程点进去会提示「本学期成绩已录入、没有需要预测的对象」——这是正常的，不是故障。

### 场景二：学业预警（学生视角）

> **用什么账号**：`20241530` 许清和（或 `20241531` 冯亦舟）

1. 用 `20241530` 登录，左侧导航 **学业预警**
2. 课程选择里选一门 **2026-1** 的课（例如 CS301 网络软件与安全）
3. 点「生成预警」→ 看到本人的预测总评与估计区间
4. **对照演示**：再选一门历史课程（例如 2024-1 的课）→ 提示「期末成绩已经录入，没有需要预测的对象」

### 场景三：挂科重修

> **用什么账号**：
> - `20241531` 冯亦舟（本学期正在重修）
> - `20241532` 邓墨白（同班另一名重修学生）

**学生端（正在重修）**

3. 注意：**课程名里没有「（重修）」字样**——重修是同一课程号在不同学年重开，成绩单上体现

**学生端（已完成重修）**

**教师端**
1. `t1102` 登录 → **课程成绩** → 选 **2026-1 · 程序设计基础（CS102）**（重修班，2 人）
2. 名单里 `20241531`、`20241532` 都带 **「重修」**徽标
3. 这门课的成绩是**暂存**状态 → 正好演示现场录入（见场景四）

> **重修规则两条**（可在选课时演示）：
> - 已通过的课程不允许在后续学期重选（提示「该课程此前已通过，不能重复修读」）
> - 挂科的学生可以重修（需要选课批次开启「允许重修」）

### 场景四：成绩录入、提交与撤销

> **用什么账号**：`t1102` 李老师（教师端）；`admin`（教务端撤销）

**教师录入并提交**
1. `t1102` 登录 → **课程成绩** → 选 **2026-1 · 人工智能导论（CS403）**（9 名学生，成绩为暂存）
2. 逐个录入平时 / 实验 / 期末分数 → 每格失焦即保存
3. 全部录完后点 **提交** → 状态变为已提交，学生随即能在「我的成绩」看到
4. 提交前若漏录，会提示「必须录入所有选课学生的成绩」

**教师撤销自己的提交**
- 提交后点 **撤销** → 成绩回到暂存，可继续修改

**教务强制撤销（审计留痕）**
1. `admin` 登录 → **课程成绩** → 选同一门课
2. 点 **小撤销**（撤回到暂存）或 **大撤销**（删除全部成绩，需要输入课程编号二次确认）
3. 打开 **安全审计** → 可以看到这条操作及其操作人、时间、影响的行

> 教师只能撤销自己带课的成绩；教务的强制撤销会额外要求填写原因，并写入独立账本。

### 场景六：网上选课

> **用什么账号**：`20241530` 许清和（学生端）；`admin`（教务端）

**学生选课**
1. `20241530` 登录 → **网上选课**
2. 可以看到进行中的批次 **「2026-1 学期网上选课」**（范围全校不限，含 9 门课，窗口约 1 个月；

3. 每门课显示是否已选、已选人数、是否可选；不能选的会给出**具体原因**（不在范围 / 已通过 / 时间冲突 / 学分超限等）

### 场景七：组织管理

> **用什么账号**：`admin`

### 场景八：安全审计与成绩完整性

## 3. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 登录提示「账号或密码错误」 | 演示账号初始密码都是 `passwd`；`ht2020`–`ht2023` 是 `enabled=0` 的样本账号，**故意不能登录** |
| 学业预警提示「至少需要 3 年、24 条完整历史成绩」 | 该课程代码的历史样本不足。演示数据里**64 门正课全部可预测**；如果出现这个提示，说明数据被改过，用 `.\scripts\start.ps1 -ResetDb` 重建 |
| 学业预警返回成功但没有结果行 | 这门课的成绩**已经出分**——预测对象是「期末还没考」的学生。请选 **2026-1** 的课程 |
| 课程下拉里出现「测试必修…」之类的课程 | 端到端测试的残留。**重启一次服务**即可自动清理（不必加 `-ResetDb`） |
| 选课批次列表里多出「测试选课批次…」「低人数批次…」 | 同上，是端到端测试的残留（状态为已取消 / 已关闭，**不会出现在学生的可选列表里**）。重启一次服务即清掉 |
| 启动很慢（1–2 分钟） | 整库重建中，205 个账号逐个算 BCrypt 哈希。只有 `-ResetDb` 或首次建库才会这样；之后再启动是秒级 |
| 页面加载突然变慢 | 数据量或账本变长后可能触发。可用 `-Dcampus.trace.repo=true` / `-Dcampus.trace.sql=true` 启动，日志会逐条打印查询耗时 |
