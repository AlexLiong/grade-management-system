# 系统模型图

本文使用 Mermaid 保存可版本管理的模型源文件。图中的模块、表、远程接口、状态和关键类均以源码为依据；课程提交时可由支持 Mermaid 的 Markdown 工具导出 PNG/PDF。

## 4. 成绩状态图

```mermaid
stateDiagram-v2
    [*] --> NotGraded
    NotGraded --> Draft: 教师暂存正考
    Draft --> Draft: 修改正考分项
    Draft --> Submitted: 教师提交
    Submitted --> Submitted: 暂存/清空/提交/撤回补考
    Submitted --> Draft: 教师撤回或管理员小撤销
    Submitted --> Deleted: 管理员大撤销 + 双人复核
    Draft --> Deleted: 管理员大撤销 + 双人复核
    Deleted --> Draft: 恢复原快照为DRAFT
    Deleted --> Submitted: 恢复原快照为SUBMITTED
    Submitted --> Submitted: 只读查看/统计/排名
    Deleted --> [*]
```

关键不变量：正考只有草稿可由教师修改；外层正考已提交后，补考只能经专用状态信封修改。`MAKEUP_CLEAR` 仅接受已有卷面分的补考 `DRAFT`，清空分数后仍保留可编辑的 `DRAFT`；每次有效变更都写历史和外部账本，重复空清请求不写入。大撤销删除业务成绩，但账本证据不能删除；恢复是新事件，不改写旧链。

## 5. 关键时序图

### 5.1 登录与 CSRF

```mermaid
sequenceDiagram
    actor U as 用户
    participant V as Vue
    participant W as AuthController
    participant S as Spring Security
    participant G as RemoteDataGateway
    participant R as SelectInterface
    participant D as Database

    U->>V: 打开登录页
    V->>S: GET /api/auth/csrf
    S-->>V: XSRF-TOKEN Cookie
    U->>V: 输入账号和密码
    V->>W: POST /auth/login + X-XSRF-TOKEN
    W->>W: 登录限速检查
    W->>G: 结构化用户查询(GATEWAY)
    G->>R: SelectRequest + HMAC上下文
    R->>R: 验签/时间窗/nonce/允许列表
    R->>D: PreparedStatement
    D-->>R: BCrypt摘要、角色和权限关系
    R-->>G: String[][]
    W->>W: BCrypt校验并合并权限覆盖
    W-->>V: HttpOnly AUTH_TOKEN Cookie + CurrentUser
```

### 5.2 成绩暂存与提交

```mermaid
sequenceDiagram
    actor T as 教师
    participant V as GradebookView
    participant C as TeacherController
    participant B as TeacherGradeService
    participant X as GradeCryptoService
    participant G as RemoteDataGateway
    participant M as ManipulationInterface
    participant D as Database
    participant L as HashChainLedger

    T->>V: 编辑分项成绩
    V->>C: 暂存(records, expectedVersion, idempotencyKey)
    C->>B: 校验请求
    B->>B: 校验授课关系、权重=100、0~100
    B->>B: 计算正考总评/补考60封顶
    B->>X: AES-GCM加密成绩JSON
    X-->>B: ciphertext + nonce + integrity
    B->>G: TransactionRequest
    G->>M: RMI批事务 + 签名主体
    M->>M: 二次授权、幂等、状态/版本检查
    M->>D: 参数化INSERT/UPDATE
    M-->>G: true
    G-->>V: 最新草稿和版本

    C->>M: DRAFT -> SUBMITTED事务

```

### 5.3 大撤销双人复核

```mermaid
sequenceDiagram

    participant R as RMI Data Server
    participant D as Database
    participant L as External Ledger

    A1->>W: 发起大撤销(目标, 原因)
```


## 7. 安全数据流与信任边界

```mermaid
flowchart LR
    subgraph Untrusted[不可信区]
        Input[用户输入/文件/查询参数]
        Browser[浏览器运行时]
    end
    subgraph Edge[Web信任边界]
        TLS[TLS终止]
        Validate[Bean Validation/文件限制]
        Session[JWT + CSRF + 限速]
        Policy[RBAC + 权限 + 所有权]
        Encrypt[AES-GCM成绩加密]
    end
    subgraph RemoteBoundary[RMI信任边界]
        Sign[HMAC + timestamp + nonce]
        Filter[JEP 290过滤]
        Policy2[数据库角色/权限/资源二次校验]
        Sql[允许列表 + 参数绑定]
    end
    subgraph Storage[存储区]
        Db[(密文成绩/审计)]
        Ledger[(外部哈希链)]
    end

    Input --> Browser --> TLS --> Validate --> Session --> Policy --> Encrypt --> Sign --> Filter --> Policy2 --> Sql --> Db
    Sql -.同步失败关闭、非XA.-> Ledger
```

安全测试需要逐个穿越这些边界，而不能只验证登录。例如 SQL 注入测试必须证明载荷到达 JDBC 后仍然是参数；越权测试必须证明 Web 与 RMI 两层都拒绝；成绩密文篡改测试要证明读取解密失败，账本篡改测试要证明现存链条的 HMAC/链接校验失败。`verifyLedger()` 不自动把数据库行与账本对账，数据库删除或非加密元数据修改需结合数据库审计、备份和外部锚点发现。
