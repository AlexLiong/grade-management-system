# 安全测试与应急说明

## 1. 威胁模型

系统保护的核心资产是账号凭据、学生身份信息、成绩明细、权限配置、审计证据和加密密钥。信任边界依次为浏览器、HTTPS Web 后端、RMI 内网边界、RMI 数据服务和数据库。主要攻击者包括未登录的互联网用户、试图横向越权的学生或教师、权限配置错误的管理员、能够直接修改数据库但不能取得应用密钥的运维账号，以及取得网络监听能力的攻击者。

重点威胁及处理方式：

| 威胁 | 入口 | 主要控制 | 剩余风险 |
| --- | --- | --- | --- |
| 口令撞库 | 登录接口 | BCrypt、统一失败文案、限速、审计 | 单机内存限速重启后清空，生产宜接 Redis/WAF |
| JWT 窃取 | 浏览器/XSS | HttpOnly Cookie、CSP、Vue 转义、短有效期 | 被完全控制的终端仍可发起同源请求 |
| CSRF | 所有写接口 | SameSite Cookie、CSRF Token、来源限制 | 错误的反向代理配置可能破坏来源判断 |
| 水平越权 | 学生/教师接口 | 不信任请求中的主体编号，按登录身份和授课关系重建过滤条件 | 组织数据配置错误仍需管理员复核 |
| SQL 注入 | 查询、筛选、批量录入 | schema 允许列表和参数绑定；禁止传 SQL | 数据库驱动自身漏洞不在应用层可完全消除 |
| RMI 未授权调用 | RMI 端口 | 网络隔离、签名上下文、时间窗、防重放、二次授权、序列化过滤 | 开发模式关闭 TLS 时元数据仍可能被同机监听 |
| 数据库直接改分 | 数据库账号 | 成绩密文 AES-GCM/HMAC 在读取时验真；关键事件保留数据库外加密快照 | DB 行删除和未纳入成绩 HMAC 的元数据修改不会由账本校验自动发现；同时取得数据库、应用密钥和账本写权限的攻击者风险更高 |
| 日志抵赖/删除 | 管理员操作 | 数据库审计 + 数据库外追加链；链首到链尾校验现存条目 | 单机账本不是多节点公链；没有外部 head/count 锚点时，整文件删除或合法尾截断可能显示为有效空链/短链 |
| 资源耗尽 | 分页、上传、登录、RMI | 页长、请求体、文件大小和速率限制；健康检查 | 课程实现未部署独立 WAF/流量清洗 |

## 2. 自动化测试入口

后端测试从工程根目录运行：

```bash
mvn test
```

前端测试和生产构建：

```bash
cd web-frontend
npm test
npm run build
```

所有安全测试必须使用专用演示数据，不得对真实学生数据或未授权网络目标执行扫描。

## 3. 手工安全用例

### 3.1 认证与会话

1. 连续使用错误密码登录，确认达到阈值后返回 `429`，且响应不说明账号是否存在。
2. 修改 JWT 任意一个字符，确认受保护接口返回 `401`。
3. 清除 CSRF 请求头后发送成绩提交，确认请求被拒绝。
4. 检查 Cookie 包含 `HttpOnly`、`SameSite`；HTTPS 模式还应包含 `Secure`。
5. 登出后重放旧请求，确认不能继续访问。

### 3.2 授权与资源隔离

1. 学生 A 修改请求路径或参数中的学生编号为学生 B，确认服务端仍只返回 A 或直接拒绝。
2. 教师 A 请求教师 B 的开课班和成绩修改接口，确认返回 `403`。
3. 分别移除管理员的 `GRADE_REVERT_SMALL`、`GRADE_REVERT_REQUEST`、`GRADE_REVERT_APPROVE` 权限后尝试小撤销、发起大撤销和审批，确认后端拒绝，而不只是隐藏菜单。
4. 直接调用 RMI 服务并伪造主体、角色或过期签名，确认远端拒绝。

### 3.3 注入与前端脚本

1. 在课程名筛选中提交 `' OR 1=1 --`，结果只能按普通文本匹配，不能返回全部数据。
2. 提交未知字段名、表资源键或排序方向，确认服务端返回参数错误且不执行 SQL。
3. 在成绩分析文字中保存 `<img src=x onerror=alert(1)>`，页面应显示文本且不执行脚本。
4. 检查生产响应包含 CSP、`X-Content-Type-Options`、`Referrer-Policy` 和 frame 限制。

### 3.4 事务、幂等与并发

1. 在一个批量录入事务中构造第二条非法成绩，确认第一条也未保存。
2. 使用相同幂等键重复提交同一批成绩，确认数据库只产生一组变更。
3. 两个请求携带相同旧版本修改同一成绩，确认后一请求收到冲突而不是覆盖。
4. 在服务端提交后、客户端收到响应前模拟断线，再使用同一幂等键重试，确认结果唯一。

### 3.5 完整性与恢复

1. 正常提交成绩，记录页面显示的账本链状态、链条目数和成绩，并保存独立账本副本及链头/count 锚点。
2. 停止应用后直接修改数据库中的成绩 `ciphertext`、`nonce` 或 `integrity`，重启并读取该成绩；确认逐行 HMAC/解密失败关闭，而不是展示伪造分数。
3. 恢复演示数据库，复制账本后改动一个非末尾条目的内容或链接，再运行 `/integrity/verify`；确认报告首个无效序号。该接口只校验账本自身，不把当前数据库行与账本自动对账。
4. 管理员从仍有效的数据库外证据读取最近快照并恢复；确认数据库内恢复和审批消费原子完成，恢复动作同步追加新的非 XA 链事件。
5. 分别删除整份测试账本和按完整行截掉链尾；确认未配置外部锚点时它们可能表现为有效空链/短链，再用事先保存的链头/count 或不可变异地副本发现差异。

### 3.6 AI 与隐私

1. 用包含明显离群值的班级成绩触发 `3 sigma`/百分位检测，确认产生异常告警和审计事件。
2. 使用至少三个学年的同课程样本运行线性回归与决策树，确认返回系数、预测区间、风险等级和树规则。
3. 刷新页面并查询正式成绩数据，确认预测值未持久化。
4. 学生 A 请求学生 B 的预测结果，确认拒绝；授课教师可读取本人开课班学生的结果。
5. 上传超类型或超大小 OCR 文件，确认在调用外部服务前被拒绝；检查本地无上传文件残留。

## 5. 备份与应急响应

1. 发现异常：冻结相关账号和高风险写权限，保留 Web、RMI、数据库审计和外部账本副本，不立即覆盖证据。
2. 确认范围：校验现存账本链，结合外部链头/count 锚点、数据库备份与双份日志按请求号关联，确定受影响用户、课程、成绩和时间窗；不要把链校验当作数据库自动对账。
3. 控制风险：轮换 JWT、RMI 签名、成绩加密和数据库凭据；关闭暴露端口；修复漏洞。
4. 恢复数据：从已验证备份和外部原始快照恢复，在隔离环境先校验，再由授权管理员执行恢复。
5. 恢复服务：先只读开放，验证权限矩阵和关键交易，再恢复写入。
6. 复盘：记录根因、影响、处置时间线和长期措施；安全事件记录不得包含明文密码、令牌或密钥。

H2 演示数据库和数据库外账本应作为两个独立备份对象；链头哈希和条目数还应写入第三方不可变锚点。生产部署至少每日全量备份、加密保存、异地复制并定期做恢复演练；未实际做过恢复演练的备份不能视为可用。
